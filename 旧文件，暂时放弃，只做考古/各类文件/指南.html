1. 你的硬件够用吗？(4060 笔记本分析)

在开始之前，我们需要了解你的装备极限。RoboTwin 涉及仿真（吃CPU和显存）和训练（吃显存）。

显存 (VRAM) 预算: 8GB

注意：如果你开着浏览器和IDE，可用显存会更少。

潜在风险点

  • 显存溢出 (OOM): RoboTwin 如果并行环境开太多，8GB 显存会瞬间爆满。
  • 散热降频: 笔记本长时间训练会过热，导致速度变慢。建议垫高电脑或使用散热架。
  • 存储空间: 机器人数据非常占硬盘。

2. 复现路线图 (Step-by-Step)

当前阶段: 环境配置

搭建地基：环境配置 (预计 3-5 天)

这是最容易放弃的阶段。你需要安装 Python, CUDA, 和仿真器。对于 4060 笔记本，建议使用 Conda 虚拟环境。

1. 显卡驱动与 CUDA

确保安装了 NVIDIA Driver 535+。安装 CUDA 11.8 或 12.1 (根据 PyTorch 版本决定，推荐 12.1)。

nvidia-smi # 检查驱动是否正常
nvcc -V # 检查 CUDA 编译器版本
2. Conda 环境

不要污染本机环境！创建一个隔离的盒子。

conda create -n robotwin python=3.8
conda activate robotwin
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121
3. 仿真器 (Isaac Sim / Isaac Gym)

RoboTwin 依赖 Omniverse Isaac Sim。你需要去 NVIDIA 官网注册下载 Launcher。

4060 注意：Isaac Sim 极其吃显存。启动时关掉所有其他软件。

生成数据：让机器人自己玩 (预计 3-7 天)

这是 RoboTwin 的核心。通过“数字孪生”生成双臂协作的演示数据。你的电脑需要长时间高负荷运行。

任务配置

先从简单的任务开始，不要一上来就跑全量数据。

  • 修改配置文件 `config/task/dual_arm_lift.yaml`
  • 设置 `num_envs = 4` (默认可能是 64 或更多，4060 跑不动)
  • 设置 `headless = True` (不渲染画面，节省大量显存)

验证数据质量

跑完10条数据后，必须通过可视化脚本检查。

python visualize_dataset.py --path ./data/demo_01
# 观察机器人动作是否鬼畜，物体是否穿模
💡 省空间技巧： 即使是 hdf5 格式，图像数据也很大。如果你只复现状态(State-based)策略，可以在配置中关掉 RGB 摄像头渲染，只保存关节角度和物体位置，体积会缩小 100 倍。

炼丹时刻：模型训练 (预计 2 天/模型)

我们将使用生成的演示数据训练模仿学习策略 (如 Diffusion Policy 或 ACT)。

Batch Size 是关键

4060 显存有限，默认的 Batch Size (通常 128 或 256) 肯定会报错。

  • Action: 在训练脚本中找到 `batch_size`，改为 16 或 32。
  • Result: 训练会变慢，但能跑通。

正常训练的 Loss 曲线示意图（你应该看到蓝线趋势）

期末考试：评估验证 (预计 1-2 天)

模型训练好了，把它放回仿真环境中，看它能不能完成任务。

👀
定性评估
开渲染看一眼，动作是否流畅，有没有卡死。
📊
定量评估
跑 100 次任务，统计成功率 (Success Rate)。
🛡️
鲁棒性测试
稍微改改物体位置，看模型会不会傻掉。
如果成功率为 0%： 不要慌。
  • 检查数据是否归一化 (Normalization) 了？
  • 检查观察空间 (Observation Space) 是否和训练时一致？
  • 检查 Action 是否需要反归一化？

3. 什么时候找老师汇报？(进度检查表)

不要等到最后才说话。按以下里程碑汇报，既能展示进度，又能及时获得算力支持。

关键里程碑

环境跑通，能看到示例Demo
已生成小规模数据 (约100条)
模型 Loss 开始稳定下降
本地显存不够 / 训练太慢

汇报话术与行动建议

点击左侧里程碑，查看对应的汇报策略...

✅ 汇报时机：本周组会 / 遇到报错超过2天

"老师，我已经配好了 RoboTwin 的环境，并且成功跑通了官方的 demo 脚本。目前 4060 显卡可以运行小规模仿真。"
目的：证明你有动手能力，且第一阶段已完成。

✅ 汇报时机：开始大规模生成前

"我已经尝试生成了 100 条数据，并可视化检查过，质量没问题。现在准备开始挂机跑 1000 条数据，预计需要 3 天。"
目的：管理预期，告诉老师这几天电脑在干活，不是你在摸鱼。

✅ 汇报时机：获得初步结果时

"基于小样本数据的初步训练结果出来了，Loss 曲线正常收敛。但是目前 Batch Size 只能开到 16，训练波动比较大。"
目的：展示进展，暗示可能需要更好的硬件来优化结果。

🚨 申请算力时机：OOM 报错无法解决时

"老师，我在尝试复现完整版论文参数时，4060 显存不足 (OOM)。我已经尝试过减小 Batch Size 和混合精度训练，但仍然受限。能否申请使用实验室服务器跑最终的训练？我可以把代码和数据整理好上传。"
关键点：先说你做了哪些优化努力（减小BS、混合精度），再说硬件不行，老师才会痛快给算力。
