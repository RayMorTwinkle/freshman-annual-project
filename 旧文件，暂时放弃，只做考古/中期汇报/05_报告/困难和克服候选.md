# 中期实验遇到的困难与克服方案

> 用于 PPT "困难与下一步计划" 页和中期报告 "现存重难点" 部分。

---

## 困难 1：LeRobot 安装会覆盖 ROCm PyTorch

**问题**：`pip install "lerobot[smolvla]"` 会自动拉取 CUDA 版 PyTorch（`torch-2.7.1`），覆盖系统预装的 ROCm PyTorch 2.10，导致 GPU 不可用。

**影响**：如果在安装阶段不阻断，模型推理和训练将完全无法使用 GPU。

**解决方案**：先用 `pip install lerobot --no-deps` 跳过依赖，再手动单独安装所需包（datasets、transformers、draccus 等），确保不触及系统 torch。

---

## 困难 2：Python 3.12 下 lerobot 0.5.1 GR00T policy dataclass 不兼容

**问题**：lerobot 0.5.1 自带的 GR00T policy 在 Python 3.12 下触发 dataclass 字段顺序错误（`TypeError: non-default argument 'backbone_cfg' follows default argument`），导致 `import lerobot` 即失败。

**影响**：完全阻挡 LeRobot 框架的使用。

**解决方案**：SmolVLA 不依赖 GR00T。通过 sed 注释掉 `policies/__init__.py` 和 `policies/factory.py` 中三处 GR00T 相关导入和调用，将条件分支改为 `if False`。

---

## 困难 3：HuggingFace 被墙，无法下载模型和数据

**问题**：PAI-DSW 服务器在国内，直接访问 `huggingface.co` 返回 `Network is unreachable`。

**影响**：无法下载 `lerobot/smolvla_base` 模型权重和 `lerobot/svla_so101_pickplace` 数据集。

**解决方案**：设置环境变量 `HF_ENDPOINT=https://hf-mirror.com`，使用国内 HF 镜像站，下载速度可达 45MB/s。

---

## 困难 4：部分 Python 包在阿里云镜像缺失

**问题**：`num2words`（SmolVLM processor 的依赖）在阿里云 PyPI 镜像上没有缓存。

**影响**：模型加载阶段报 `ImportError: Package num2words is required`。

**解决方案**：临时切到中科大镜像 `pip install num2words -i https://mirrors.ustc.edu.cn/pypi/web/simple/`，下载成功。

---

## 困难 5：AMD ROCm 容器缺少 FFmpeg 共享库，torchcodec 解码失败

**问题**：读取 LeRobot 数据集时，torchcodec 尝试加载 `libavutil.so.56/57/58/59/60`（FFmpeg 各版本），均因缺失共享库而失败，导致无法读取视频帧。

**影响**：数据集读取链路断裂。

**解决方案**：改用 `pyav` 作为视频解码后端（`LeRobotDataset(DATASET_ID, video_backend="pyav")`），pyav 基于 Python 的 av 库，不依赖系统 FFmpeg 动态链接库。

---

## 困难 6：ngrok 免费版要求绑定信用卡

**问题**：原计划用 ngrok 内网穿透实现远程 SSH，但 ngrok 免费版现在强制要求绑定信用卡才能使用 TCP 隧道（`ERR_NGROK_8013`）。

**影响**：无法通过 SSH 直接操作远程服务器，只能通过 JupyterLab Terminal 逐条粘贴命令。

**解决方案**：改用 Cloudflare Tunnel（Zero Trust），免费、不需要信用卡、国内访问速度也更快。同时配置本地 SSH alias `ssh dsw` 一键连接。

---

## 困难 7：pip 版本冲突告警

**问题**：`--no-deps` 安装导致部分包版本高于 lerobot 要求的范围（如 draccus 0.11.5 vs 0.10.0、av 17.0.1 vs <16.0.0、setuptools 82.0.1 vs <81.0.0），pip 输出大量 `dependency conflict` 警告。

**影响**：心理层面有压力，但经逐一验证，推理链路实际不受影响——真正影响功能的只有 GR00T dataclass 和 torchcodec 库缺失，其余版本差异未触发运行时错误。

**解决方案**：对核心解析依赖（draccus）指定版本 `draccus==0.10.0`，其余兼容性警告经测试不影响推理链路，忽略处理。

---

## 总结

| 类别 | 困难数 | 代表性困难 |
|---|---|---|
| 环境兼容 | 4 个 | ROCm vs CUDA torch、Python 3.12 dataclass、FFmpeg 库缺失、pip 版本冲突 |
| 网络访问 | 2 个 | HuggingFace 被墙、阿里云镜像缺包 |
| 远程接入 | 1 个 | ngrok 要绑信用卡 → 换 Cloudflare Tunnel |
| **总计** | **7 个** | 全部解决，推理链路已跑通 |

**中期汇报口径建议**：

> 在实验环境搭建过程中，我们遇到了多个技术障碍，包括 ROCm/CUDA 环境兼容性问题、HuggingFace 网络访问限制、Python 3.12 与 LeRobot 框架的兼容性问题、以及 AMD 容器缺失视频解码库等。我们通过逐一排查、查阅文档和社区资源，采用 `--no-deps` 安装策略、国内镜像加速、pyav 替代 torchcodec、注释不兼容模块等方式，最终在 AMD ROCm 平台上成功跑通了 SmolVLA 的完整推理链路，并实现远程 SSH 接入以便高效调试。
