# 9. 2:20–2:50 做“异步推理小心意”

SmolVLA 论文里很适合你们项目主题的点是 async inference。论文结果显示，异步推理在保持相近成功率的同时，把平均完成时间从 13.75s 降到 9.70s，并在固定时间内完成更多 pick-place 次数。
你们没有真机器人，也可以复现核心思想：**同步推理会等 action queue 空了再算下一段动作；异步推理会在队列还没空的时候提前请求下一段动作。**

## 9.1 生成异步推理队列图

复制：

```bash
cd ~/midterm_vla

cat > scripts/async_queue_demo.py <<'PY'
from pathlib import Path
import csv
import matplotlib.pyplot as plt

Path("figures").mkdir(exist_ok=True)

def simulate_sync(total_steps=260, chunk_size=50, inference_steps=12):
    """
    同步模式：
    1. 先有一段动作队列
    2. 队列执行完以后，机器人停下来等模型推理
    3. 推理完成后再拿到下一段动作
    """
    q = chunk_size
    wait = 0
    sizes = []
    idle_steps = 0

    for t in range(total_steps):
        if q > 0:
            q -= 1
        else:
            idle_steps += 1
            wait += 1
            if wait >= inference_steps:
                q = chunk_size
                wait = 0
        sizes.append(q)

    return sizes, idle_steps

def simulate_async(total_steps=260, chunk_size=50, inference_steps=12, threshold=0.7):
    """
    异步模式：
    当队列剩余比例低于 threshold 时，提前开始推理。
    模型推理的时候，机器人继续执行旧队列。
    推理完成后，队列被补满。
    """
    q = chunk_size
    request_in_flight = False
    remaining_infer = 0
    sizes = []
    idle_steps = 0

    for t in range(total_steps):
        if q > 0:
            q -= 1
        else:
            idle_steps += 1

        # 队列低于阈值，而且当前没有请求，就发起新请求
        if (q / chunk_size) < threshold and not request_in_flight:
            request_in_flight = True
            remaining_infer = inference_steps

        # 如果请求正在进行，就倒计时
        if request_in_flight:
            remaining_infer -= 1
            if remaining_infer <= 0:
                # 新 action chunk 到达，简单处理为补满队列
                q = chunk_size
                request_in_flight = False

        sizes.append(q)

    return sizes, idle_steps

sync_sizes, sync_idle = simulate_sync()
async_sizes_05, async_idle_05 = simulate_async(threshold=0.5)
async_sizes_07, async_idle_07 = simulate_async(threshold=0.7)

plt.figure(figsize=(10, 5))
plt.plot(sync_sizes, label=f"sync, idle steps={sync_idle}")
plt.plot(async_sizes_05, label=f"async g=0.5, idle steps={async_idle_05}")
plt.plot(async_sizes_07, label=f"async g=0.7, idle steps={async_idle_07}")
plt.xlabel("Control step")
plt.ylabel("Action queue length")
plt.title("SmolVLA-style synchronous vs asynchronous action queue")
plt.grid(True, alpha=0.3)
plt.legend()
plt.tight_layout()
plt.savefig("figures/async_queue_demo.png", dpi=200)

with open("figures/async_queue_summary.csv", "w", newline="") as f:
    writer = csv.writer(f)
    writer.writerow(["mode", "idle_steps"])
    writer.writerow(["sync", sync_idle])
    writer.writerow(["async_g_0.5", async_idle_05])
    writer.writerow(["async_g_0.7", async_idle_07])

print("Saved figures/async_queue_demo.png")
print("Saved figures/async_queue_summary.csv")
print("sync idle steps:", sync_idle)
print("async g=0.5 idle steps:", async_idle_05)
print("async g=0.7 idle steps:", async_idle_07)
```

## 13.2 项目研究内容及实施方案

```text
本项目计划采用“仿真数据生成—轻量化策略训练—端侧推理优化”的技术路线。RoboTwin 2.0 作为双臂操作仿真数据生成与评测平台，提供多任务、多物体、多机器人形态和强域随机化能力，可用于生成专家轨迹并评估策略鲁棒性。SmolVLA 作为轻量化 Vision-Language-Action 模型，使用 compact VLM 和 Action Expert，将图像、语言和状态编码后输出连续动作 chunk，适合端侧或消费级硬件部署。

本阶段实施方案包括三部分：第一，完成两篇论文的阅读和技术路线分析，明确 RoboTwin 2.0 与 SmolVLA 在本项目中的分工；第二，搭建 LeRobot/SmolVLA 实验环境，使用公开数据集进行小步数训练，以验证模型加载、数据读取和训练流程；第三，尝试 RoboTwin 2.0 环境配置和数据采集命令，分析当前 AMD/ROCm 平台与官方推荐环境之间的差异，并设计后续迁移方案。
```

## 13.3 进展情况和初步成果

```text
本阶段已经完成 RoboTwin 2.0 与 SmolVLA 的文献调研。RoboTwin 2.0 的主要贡献在于构建大规模双臂操作数据生成平台，通过 MLLM 生成专家任务代码，并结合仿真执行日志和 VLM 观察反馈进行代码修正，同时使用杂物、光照、背景、桌面高度和语言表达等域随机化提升策略鲁棒性。SmolVLA 的主要贡献在于构建较小规模的 VLA 模型，通过减少视觉 token、跳过部分 VLM 层、使用 Action Expert 和异步推理机制降低训练与推理成本。

实验方面，本阶段已在 AMD/ROCm 服务器上完成 PyTorch 与 GPU 可用性检查，并搭建 LeRobot/SmolVLA 环境。基于 lerobot/smolvla_base 和公开 SO100 pick-place 数据集，完成了小步数 fine-tuning smoke test，验证了模型加载、数据读取、训练日志输出等基础链路。同时，针对 SmolVLA 的异步推理思想，设计了 action queue 仿真实验，对比同步推理和异步推理下队列长度变化，说明异步机制能够减少动作执行过程中的等待空窗。

RoboTwin 2.0 方面，本阶段完成了官方文档、仓库结构和数据采集命令的调研，并尝试进行环境配置。由于当前可用服务器为 AMD/ROCm 环境，而官方文档推荐 CUDA 12.1 且 GPU simulation 标注为 NVIDIA GPU，因此本阶段将 RoboTwin 2.0 作为仿真数据平台完成了环境适配验证，后续计划迁移到 NVIDIA CUDA 环境进行正式数据采集。
```

## 13.4 遇到的困难与下一步计划

```text
当前主要困难包括：第一，RoboTwin 2.0 对底层仿真、Vulkan、SAPIEN、CuRobo 和 GPU simulation 依赖较强，当前 AMD/ROCm 平台存在兼容性风险；第二，RoboTwin 仿真轨迹与 SmolVLA/LeRobot 训练格式之间仍需设计数据转换流程；第三，当前实验仅为小步数 smoke test，尚不能代表最终策略成功率。

下一阶段计划包括：首先，在更适配的 NVIDIA CUDA 环境中完成 RoboTwin 2.0 小任务数据采集，优先选择 beat_block_hammer、stack_blocks_two、pick_dual_bottles 等相对稳定任务；其次，研究 RoboTwin 输出数据结构，设计到 LeRobotDataset 的转换脚本；再次，开展 clean 数据与 domain randomized 数据的对比实验，分析域随机化对策略鲁棒性的影响；最后，在 SmolVLA 侧继续研究异步推理、低精度推理和模型压缩，使模型更适合端侧部署。
```

## 13.5 结题预期目标

```text
结题阶段预期形成一个面向双臂操作任务的轻量化实验原型，包括：一套 RoboTwin 小任务仿真数据采集流程，一套面向 LeRobot/SmolVLA 的数据处理与训练流程，一组 clean 与 randomized 数据对比实验结果，以及一个端侧推理优化方案。最终目标是完成“仿真数据生成—轻量化 VLA 策略训练—端侧低延迟推理”的完整技术链路，为后续真实双臂机器人部署提供基础。
```
