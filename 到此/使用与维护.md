
## 首次登录与 CPU 测试

在自己的交互终端中执行；首次按提示打开 Google 授权链接并输入授权码。授权码和令牌不要写入文档或公开仓库。

```bash
colab --auth=oauth2 new -s annual-cpu
colab --auth=oauth2 status -s annual-cpu
echo 'print("Hello Colab")' | colab --auth=oauth2 exec -s annual-cpu
colab --auth=oauth2 stop -s annual-cpu
```

成功后再尝试 GPU：

```bash
colab --auth=oauth2 new -s annual-gpu --gpu T4
colab --auth=oauth2 exec -s annual-gpu -f train.py
colab --auth=oauth2 stop -s annual-gpu
```

`train.py` 是你需准备的本地脚本。免费账户是否能分配 GPU、能运行多久由服务端决定；CLI 不增加免费配额。网页和 CLI 都使用 Colab 后端，CLI 便于本地脚本与自动化，网页便于交互式 Notebook。高内存选项要求相应订阅资格。

## 文件与结果

```bash
colab --auth=oauth2 upload -s annual-gpu ./input.csv /content/input.csv
colab --auth=oauth2 download -s annual-gpu /content/result.csv ./result.csv
colab --auth=oauth2 sessions
```

执行脚本内容不等于自动上传整个项目。脚本用到的数据、模块等需另外准备。停止实例前先保存结果。

一次性任务也可用 `colab --auth=oauth2 run --gpu T4 train.py`；默认结束后释放实例。使用前用 `colab run --help` 查看当前版本选项。

```bash
uv tool upgrade google-colab-cli

uv pip list --python /Users/ray/.local/share/uv/tools/google-colab-cli/bin/python
```

更新后重新保存依赖快照、版本及日志。若要回到本次版本：`uv tool install --python 3.12 --force google-colab-cli==0.7.5`；传递依赖仍可能变动，完整旧版本列表见快照。

连接失败时记录命令、版本、时间和脱敏报错。区分本地启动错误、OAuth 授权错误和云端配额/网络错误，不要把 GPU 分配失败直接当成安装失败。

## 卸载与腾空间

1. 先查询并停止仍在运行的云端实例，下载需要保留的结果。卸载本机 CLI 不会自动停止云端实例。
2. 执行 `uv tool uninstall google-colab-cli`，由 uv 移除专用环境与命令入口。
3. 不再使用时，可在 Finder 用“前往文件夹”检查并删除 `~/.config/colab-cli/` 中的会话/凭证/设置；删除本地令牌不等于撤销 Google 端授权，需要时到 Google 账号的第三方连接管理中撤销。自定义 OAuth 配置仅在确认专属时清理。
4. 如要额外清 uv 缓存，先运行 `uv cache clean --help`，可尝试按包清理 `uv cache clean google-colab-cli`。它不保证清掉全部依赖缓存。整个 `uv cache clean` 会清共享缓存，影响其他工具后续下载，勿把整个目录视为本项目专用。
5. 保留原有 uv、共享 Python 3.12、Conda 和 strix-agent，除非另行核查确实不再需要。
6. 删除项目文件夹本身不会卸载用户目录里的 CLI；项目中的 `.git` 也会占空间，可用 `du -sh` 单独统计。当前公开仓库曾上传虚拟环境，因此仅在后续提交中删除环境并不会自动缩小历史数据。

## 实验经验：节省 GPU 时间与应对断连

来源：用户转述的他人实践经验，2026-11-03 收录；具体收益尚未在本项目验证。

1. **先在 Colab CPU 环境完成代码开发和数据预处理。** 尽量在 CPU 上验证数据读取、清洗、格式转换及基本逻辑，确认流程正确后再申请 GPU，减少 GPU 实例等待和调试的时间。需要 GPU 的预处理或 CUDA 代码仍需在 GPU 上验证；切换实例前，将代码和预处理结果保存到 Drive 等持久存储。
2. **训练时每 10–20 分钟保存一次可恢复的 Checkpoint。** 以此作为初始建议间隔，按保存耗时与可接受损失调整。保存到 Google Drive 等持久存储，不能只留在实例临时目录 `/content`。除模型权重外，按框架保存优化器、学习率调度器、训练步数/轮次及所需随机状态、混合精度缩放器状态等。实际做一次中断后恢复测试，确认能续训，降低突然断开造成的损失。
